Setup as in [e4.md](e4.md): 24 GiB UMA, OpenCode 1.18.32, `LLAMA_ARG_CACHE_RAM=1024`, f16 KV, screening3 tier
(tasks 001, 004, 005, 007, 009, 011, three repeats each), 30-minute limit per attempt. Only the runtime changes.
Ollama 0.34.4 (its bundled ROCm llama.cpp) is compared with `llama-server` run directly:

- **Vulkan:** ggml-org release b12191 (RADV), `/srv/agentbench/opt/llama/vulkan-b12191/`.
- **ROCm:** lemonade-sdk llamacpp-rocm b1370 for gfx1150 (ROCm 10.3.0a20261107, upstream b12189),
  `/srv/agentbench/opt/llama/rocm-b1370/`.

## Findings

- **No runtime beats Ollama.** Pass counts are within one of Ollama for both models (12-13/18 qwen, 13-14/18
  laguna), which is noise for one screen. Ollama stays best or tied on solved per 8 h: qwen 147.7 against about 132,
  laguna 34.0 against 33.1 (Vulkan) and 24.8 (ROCm).
- **llama.cpp processes prompts faster but generates more slowly.** Prompt processing is 1.4-2.9x Ollama's (the
  `-b 2048` default batch against Ollama's 512), but agent generation is 12% slower for qwen and 27-52% slower for
  laguna. These attempts are dominated by generation, so the net is a loss.
- **ROCm b1370 slows down as the context grows.** On short attempts it matches Vulkan (about 24 tok/s), but on
  laguna's long attempts (005, 007, 011) it falls to 12-14 tok/s, against 20-25 for Vulkan. That gave it three
  timeouts and the worst laguna throughput. Vulkan is the better of the two llama.cpp builds.
- **The generation gap to Ollama is not explained.** `llama-bench` gives 38 tok/s at empty context for both builds,
  and Ollama reaches 50 tok/s on laguna's short attempts, so the loss is in how llama-server ran here, not the
  kernels alone. Untested candidates: flash attention (`auto` in both, but the two may resolve it differently), the
  `-ub`/`-b` batch sizes, and llama-server's prompt cache handling. Closing it would need another round of probes.
- **Confounds.** laguna uses the GGUF's own chat template under llama.cpp instead of Ollama's `poolside-v1`
  renderer and parser; tool calls worked in every attempt, but prompts are not byte-identical. Sampling was copied
  from the Ollama modelfiles.
- **Recommendation:** keep Ollama 0.34.4. It needs no extra binaries, keeps the model renderers and parsers, and is
  as fast or faster end to end. Proposed next: E5 finalists (qwen3-coder 32k and laguna 64k/128k on Ollama).
