Infra errors: 5 across the E4 runs, all ssh timeouts from newbuntu, retried. No OOM kills.
Laguna is only published as Q4_K_M or BF16 (62 GiB), so it has no quant rows. qwen Q6_K (23.4 GiB) and Q8_0
(30.3 GiB) leave no room for the KV cache in 24 GiB.

`e4-qwen-udq4` and `e4-qwen-udq5-kvq8` (both 4/18) are kept as evidence of a trap: a GGUF pulled from Hugging Face
(`hf.co/unsloth/...`) uses the template embedded in the file and has no Ollama `RENDERER`/`PARSER`, so OpenCode's
tool calls were not parsed and most attempts ended after about 400 tokens. The `t` re-runs use the same weights
rebuilt with `RENDERER qwen3-coder`, `PARSER qwen3-coder` and the library model's sampling parameters.

## Findings

- **Weights quant makes no measurable difference for qwen3-coder.** UD-Q4_K_XL and UD-Q5_K_XL both score 11/18,
  the same as Q4_K_M. UD-Q4 is a little smaller (fits fully on the GPU) at about the same speed; UD-Q5 is slower
  and spills 5%. There is no reason to move off the library Q4_K_M.
- **8-bit KV is a net loss on this GPU.** It makes qwen fit fully, but generation drops 17-34% (qwen 27.4 -> 22.6,
  laguna 34.4 -> 22.8 tok/s), and laguna scored 11/18 instead of 14/18. Use f16 KV.
- **Context length matters more than quant, and differently per model.**
  - qwen3-coder: 32k is as good as 64k (12/18) and slightly faster; 128k adds nothing. Its attempts are short
    (median 2k generated tokens), so it never needs the room.
  - laguna: 32k makes it much faster (median 3.4 vs 9.0 min, 54.9 vs 34.0 solved per 8 h) for 12/18; 128k gave
    the best score of any run (15/18, and the first 3/3 on 011-status-effects) but spills 10% of the model and uses
    up to 7.1 GiB RAM and 2.0 GiB swap, which leaves little room for a larger Godot project.
  - Each change is one screen of 18 attempts; one or two passes either way is within noise. The pooled laguna
    64k figure over two screens is 26/36 (0.72) against 15/18 (0.83) at 128k.
- **Recommendation for now:** qwen3-coder:30b Q4_K_M, f16 KV, 32k context for throughput (the overnight queue);
  laguna 128k when first-time success matters more than speed, with laguna 64k as the safer memory choice.
  Confirming laguna 128k against 64k needs the finalists tier (12 tasks x 3) in E5.
- Proposed next: E2 (runtime: llama.cpp directly, Vulkan vs ROCm) with qwen 32k and laguna 64k/128k, then E5
  finalists.
